# Чек-листы СМП

Формулировки описывают, **что** проверить. Конкретные данные, шаги и ожидаемые результаты находятся в `test-design.md`.

## Дымовое тестирование

### Инфраструктура и доступность

- [ ] Docker Compose поднимает обязательные сервисы, PostgreSQL и RabbitMQ без циклических рестартов.
- [ ] Health-check Gateway, Card-Management, Switch, Authorization, Terminal Simulator, Merchant/Acquirer Simulator, Transaction Logger, Bin Lookup и Notification Service возвращает штатный статус.
- [ ] RabbitMQ Management UI доступен. Exchanges `smp.transactions`, `smp.card-events` и связанные очереди объявлены.
- [ ] Dashboard открывается без ошибок загрузки ресурсов. WebSocket к Transaction Logger устанавливается.
- [ ] В логах старта нет ошибок миграций, секретов и полного PAN.

### Минимальная работоспособность сервисов

- [ ] Card-Management создает карту с 16-значным PAN, валидным Luhn, `ACTIVE` и `expiryDate` в MMYY.
- [ ] Card-Management генерирует не менее 20 карт и возвращает их через пагинированный список.
- [ ] Gateway принимает валидную транзакцию и передает ее в Switch.
- [ ] Switch маршрутизирует известный BIN в Authorization.
- [ ] Authorization одобряет валидную транзакцию и возвращает RRN из 12 цифр, authCode из 6 символов и `responseCode=00`.
- [ ] После одобрения доступный баланс уменьшается ровно на сумму операции.
- [ ] Transaction Logger получает и сохраняет транзакцию. Поиск по RRN возвращает одну запись.
- [ ] Dashboard показывает новую транзакцию и обновленные агрегаты.
- [ ] Notification Service получает карточное событие, опубликованное outbox-процессором.

## Критический путь

### Одобренная покупка

- [ ] Terminal Simulator выбирает существующую `ACTIVE`-карту с неистекшим сроком.
- [ ] Gateway валидирует обязательные поля, не изменяя STAN и денежную сумму.
- [ ] Switch извлекает BIN и направляет запрос правильному issuer/Authorization.
- [ ] Authorization использует Bin Lookup. При его недоступности применяется предусмотренный fallback issuerId.
- [ ] Authorization проверяет статус, срок, дневной лимит, месячный лимит и баланс именно в заданном порядке.
- [ ] Card-Management выполняет единственное резервирование с тем же PAN, amount и RRN.
- [ ] Ответ содержит `APPROVED`, `00`, уникальные RRN и authCode.
- [ ] `availableBalance`, `daily_amount` и месячное использование увеличиваются/уменьшаются ровно один раз.
- [ ] Switch получает publisher confirm до возврата окончательного успешного результата.
- [ ] Logger сохраняет ровно одну запись, а Dashboard отображает согласованные данные с замаскированным PAN.

### Обоснованное отклонение

- [ ] Неизвестный PAN дает `DECLINED/14` без резервирования и изменения лимитов.
- [ ] `INACTIVE` и `BLOCKED` отклоняются с соответствующей причиной до проверки денег.
- [ ] Статус `EXPIRED` или истекший MMYY дает `DECLINED/54`.
- [ ] Превышение дневного или месячного лимита дает `DECLINED/61`.
- [ ] Недостаточный баланс дает `DECLINED/51`.
- [ ] Отклоненная транзакция журналируется один раз и не создает карточного события резервирования.

### Отказы и восстановление

- [ ] Gateway возвращает контролируемый 503/ошибку контракта при недоступном Switch и не создает побочных эффектов.
- [ ] Authorization обрабатывает недоступность Card-Management по согласованному responseCode без изменения лимитов.
- [ ] Недоступность Bin Lookup не блокирует известный BIN благодаря graceful degradation.
- [ ] При отрицательном publisher confirm Switch выполняет reversal, итоговый баланс восстанавливается, клиент получает `DECLINED/96`.
- [ ] Повтор сообщения транзакции не создает дубль в Logger.
- [ ] Ошибка consumer после трех попыток направляет сообщение в соответствующую DLQ.
- [ ] При недоступном RabbitMQ карточное событие остается в outbox для retry. Созданная карта не теряется.
- [ ] После восстановления зависимости health-check и критический путь проходят без ручного исправления данных.

## Классы верхнего уровня для периферии

| Сервис | Валидные классы | Негативные/отказные классы |
|---|---|---|
| Gateway | корректный запрос, допустимая частота | неверный формат, отсутствующее поле, >100 req/s, downstream 503 |
| Switch | известный BIN, подтвержденная публикация | неизвестный BIN, Authorization timeout, publish nack/timeout |
| Terminal Simulator | одиночный и непрерывный запуск, штатный сценарий | неизвестный сценарий, пустой пул карт, остановка выполнения |
| Merchant/Acquirer Simulator | известные merchant/terminal, валидная комиссия | неизвестный ресурс, некорректная сумма/сценарий |
| Transaction Logger | новая и повторная транзакция, поиск/экспорт | неверные фильтры, consumer retry, DLQ, лимит экспорта |
| Bin Lookup | известный BIN | неизвестный BIN, timeout/5xx и fallback |
| Notification Service | поддерживаемое `card.*`-событие | дубликат, неверная схема, retry/DLQ |
| Dashboard | пустой и непустой набор, live update, фильтры | API/WebSocket недоступен, неполные данные, XSS-текст |
